# Perform evaluation, error analysis, and tuning

Weight: 15-20%

Whether you can evaluate agent work through evidence, classify failure causes, and tune instructions, memory, tools, and workflows without hiding defects.

Lessons in this domain:

- Specify expected outcomes and operational constraints for agent tasks (domain-4-lesson-01-specify-expected-outcomes-and-operational-constraints-for-agent-tasks)
- Identify qualitative and quantitative evaluation signals to evaluate agents (domain-4-lesson-02-identify-qualitative-and-quantitative-evaluation-signals-to-evaluate-agents)
- Align evaluation criteria with development intent (domain-4-lesson-03-align-evaluation-criteria-with-development-intent)
- Generate evaluation signals by using automated scanning tools (domain-4-lesson-04-generate-evaluation-signals-by-using-automated-scanning-tools)
- Identify failures by using logs, plans, traces, outputs, and workflow artifacts (domain-4-lesson-05-identify-failures-by-using-logs-plans-traces-outputs-and-workflow-artifacts)
- Classify root causes, including reasoning errors, tool misuse, and context or environment issues (domain-4-lesson-06-classify-root-causes-including-reasoning-errors-tool-misuse-and-context-or-envir)
- Revise instructions, workflows, or constraints (domain-4-lesson-07-revise-instructions-workflows-or-constraints)
- Refine memory usage (domain-4-lesson-08-refine-memory-usage)
- Refine tool usage and tool access (domain-4-lesson-09-refine-tool-usage-and-tool-access)
- Static analysis, CodeQL, secret scanning, dependency checks (domain-4-lesson-10-static-analysis-codeql-secret-scanning-dependency-checks)
- Accessibility scans as evaluation signals (domain-4-lesson-11-accessibility-scans-as-evaluation-signals)
- Prompt and instruction failure classification (domain-4-lesson-12-prompt-and-instruction-failure-classification)
- Avoiding overfitting after tuning (domain-4-lesson-13-avoiding-overfitting-after-tuning)
- Regression checks after tuning (domain-4-lesson-14-regression-checks-after-tuning)
